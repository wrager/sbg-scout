# Анонс изменений

Базовую версию брать из запроса пользователя (например, `1.0` или `v1.0.0`). Если её нет, запросить версию. Соблюдать правила release notes из `AGENTS.md`.

1. Изучить `git tag --sort=version:refname` и найти фактический тег указанной версии. Не угадывать тег; сокращение `1.0` допустимо сопоставить с `v1.0.0`, только если выбор однозначен.
2. Собрать `git log <base-tag>..HEAD --oneline --no-merges`. Проверить итоговое поведение по коду, поскольку коммиты могут описывать промежуточные изменения.
3. Написать анонс по правилам ниже и вернуть его пользователю. Не сохранять в файл, не создавать коммит и не публиковать без отдельного запроса.

Правила текста:

- Язык — русский; простой текст без маркированных списков, пункты разделены пустой строкой.
- Новые фичи: `Добавлен функционал "название" - краткое описание` (одно предложение).
- Багфиксы одной области объединять. Отдельный коммит не означает отдельный пункт.
- Описывать итоговый результат для пользователя. Убирать детали реализации, рефакторинги, CI и правила разработки; тривиальные изменения объединять или исключать.
- Один плоский текст без разделения по версиям.
- Использовать обычные кавычки `"` и дефис `-`, без длинного тире, типографских спецсимволов и маркеров списка.
